Config Service

A typed, versioned configuration store that replaced a shared YAML file and its merge conflicts.

A dozen services shared one YAML file in a config repo, edited by hand and deployed by CI. Merge conflicts and silent typos were routine. I built a small typed config service with schema validation and an audit log, so a bad value fails at publish time instead of at runtime in a service nobody was watching.

Role
Backend developer
Status
In production
Stack
Go · PostgreSQL

Result

Config errors caught before rollout, not after

Every config change is validated against the owning service's schema before it publishes, and every publish is attributed and reversible. The class of incident caused by a bad config value reaching production dropped to zero in the following year.
