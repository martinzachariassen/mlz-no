Search Relevance Service

A standalone ranking service that took relevance tuning out of a monolith and into something product could iterate on weekly.

Role
Backend developer
Team
2 engineers
Status
In production
Stack
Kotlin · Elasticsearch · gRPC

Ranking logic lived inline in the search endpoint of the main monolith, so every relevance change needed a full deploy and a release owner. I extracted it into its own gRPC service with a config-driven scoring pipeline, so product and search specialists could ship ranking changes without engineering in the loop.

Approach

Scoring as configuration, not code

The new service reads a versioned scoring config at request time, so a ranking change is a config publish rather than a deploy. Every request also logs which config version scored it, which made the A/B rollout of new ranking strategies straightforward to attribute.

Result

Weekly ranking iteration instead of quarterly

Faster relevance iteration cycle
